## 1. 项目概述与技术规范

### 1.1 项目目标
考研 408（数据结构/计组/OS/计网）复习辅助平台。**"可视化"指用户操作（单步、拖滑块、
改输入）后界面给出即时反馈——节点变色、连线高亮、数据流动、状态切换；不是播放视频。**

### 1.2 技术栈
- HTML5 + Tailwind CSS（Play CDN，离线会缺失，有检测提示）+ 原生 JS（ES6+，经典 script 全局作用域）
- KaTeX（CDN）渲染理论区 LaTeX 公式
- SVG 优先（绑 CSS 过渡方便）
- **双击 index.html 即可运行**；开发预览用仓库自带 `serve.py 8642`（带 no-cache 头；
  **不要用 `python -m http.server`**——会缓存 js/css 导致"改了没生效"的假象）

### 1.3 核心架构：快照（Snapshot）模式 ★ 不可违背的铁律
```
parse(表单值) → buildSnapshots(model) → Snapshot[]        ← 纯算法，零 DOM
Runner 维护下标 idx（单步/自动/重置/拖进度 = 移动 idx 后重绘）  ← 框架统一提供
render({ model, snap, idx, total, stage })                 ← 纯渲染，只读快照
```
- **快照必须全量携带视觉状态**（数组要 `[...arr]` 拷贝），回退/跳帧才不出错
- 日志由 `[0..idx]` 区间快照重建，天然与画面一致
- 动画 = 给"当前帧变化的元素"挂 CSS 类，每帧 `stage.innerHTML=''` 重建 DOM 触发重放
- 两种模式：`mode:'stepper'`（有过程）｜`mode:'instant'`（参数即结果，如子网划分）

### 1.4 标准控制面板（框架自带，模块零成本复用）
生成数据 🎲 / 重置 ⏮ / 单步 ▶ / 自动播放 ▶▶（到末尾自动停）/ 速度滑块（2300−档×200ms）/
进度条（可任意拖动回放）/ 展示区缩放（－/100%/＋，改 stage 的 CSS zoom，0.5~1.5）/ 专注模式。
快捷键：→ 单步 · ← 回退 · 空格 播放暂停 · R 重置。

### 1.7 协作规则（用户明确要求，2026-09-20 追加；窗1 增补第 4 条窗号制度）
1. **发现问题直接修正记录**：开发中发现真题分析错误、考情数据错漏、文档计数/描述过时等问题，
   直接修改对应数据/文档，并同步更新本 handover（写明勘误依据），让后续窗口直接继承正确结论。
2. **一窗一模块、节约 token（粒度改由当前窗口推荐，2026-09-20 用户拍板）**：一个窗口原则上只负责
   一个模块的开发；**未经用户指令不做大规模 bug 排查/全库审计**；验证以"新模块 Node 冒烟 +
   浏览器交互实测 + 最后一次全站遍历收尾"为度。
   **是否在同一窗继续做下一个模块、还是另开窗口 → 由当前窗口按 §3.7 给出【窗口建议】**（模板见 §3.7-6，
   记录在 §6.5），用户可否决。
3. **每个窗口都必须回写经验（用户明确要求，2026-09-20 追加）**：不管你是哪个模型，收尾时都要把
   本窗**可复用的做法与踩过的坑**写进本 handover，**最重要的就是节约 token/时间的做法**（§3.5）
   与模型专属坑（§3.6）。两条硬性要求：
   ① **就地改写，不要只在末尾追加**——窗0 就犯过这个错：新加的 §3.5-12（查真题走缓存）没去改
      §3.5-1（仍写着"直接查 PDF 原文"），两条自相矛盾，后来者会照着旧条目白干；
      淘汰了旧做法就删掉或改写旧条目，让全文只有一个当前口径；
   ② **写明依据与实据**（哪一年真题、哪次实测、什么报错），不要只写结论——后来者要靠它判断可信度。
4. **窗号制度（窗1 起执行，用户 2026-09-20 拍板）**：全文到处写"（本窗…）"而日期都是 2026-09-20，
   后来者根本看不出这是哪一窗留下的、是不是已经过时。故建立窗号：
   - **窗1 = 2026-09-20 的 ds-btree 窗**（制度自本窗建立，故本窗即 1 号）；此后**每换一窗 +1**，
     **同一窗内继续做下一个模块不增号**。不知道自己该是几号时，看 §6.6 台账最后一行 +1。
   - 凡本窗**新增或改写**的经验、勘误、结论、修复，括号里必须署窗号：`（窗1 实测）`、`（窗1 改写）`、
     `（窗2 新增）`……；§6.5 顶部写 `【窗N】`，并在 §6.6 台账追加一行（最新在上）。
   - **未署窗号的"本窗/上窗/上一窗"一律视为「窗0 及更早」**（制度建立前那批窗口），
     可信度低于带窗号的条目——**引用前必须用 `考情缓存/` 或 js/ 代码复核**，不要直接照抄结论。
   - **规则、模板、操作规程里的"本窗"是泛指当前窗口，不用署号**；只有**叙述已经发生的事**
     （实测、踩坑、勘误、修复、交付）才必须署号。

5. **handover 维护是本项目的"第一优先级"（用户 2026-09-20 明确要求）**：handover 是项目的灵魂，
   每窗收尾**先把 handover 弄干净，再谈别的**。四条硬性要求：
   ① **不许留"完全过时"的经验**——被淘汰的做法必须**就地改写或删除**，不能只在末尾追加新条目（§1.7-3①）；
   ② **不许留"已经解决、却写得像还没解决"的条目**（后来者会照着它白花时间重查一遍）；
      解决即改写为「结论 + 依据 + 窗号」；
   ③ **模型专属经验与通用经验必须分开归档**：通用工程纪律 → §3.1~§3.5 与 §3.8（验证方法论）；
      **只有"某模型特有的失误倾向"才进 §3.6**，且 §3.6 内**按模型分小节 `#### 3.6.N <模型名>`**，
      新模型只写自己的小节、不动别人的。**（不要求你只写自己模型的经验——通用经验随时可补，但位置不能错：
      放错位置，别的模型看到"模型专用"就整节跳过，通用经验等于白写。）**
   ④ 每条经验结尾写明**依据**（哪一年真题 / 哪一次实测 / 什么报错）与**窗号**（§1.7-4）。
   **收尾自检一句话**："如果我是下一个窗口、且用的是另一个模型，照这份文档做，会不会踩到已经解决的坑？"

## 3. 开发经验与避坑指南（核心！）

### 3.1 架构类
1. **快照必须自包含**：曾出现模块渲染时回读 DOM 输入框取主串（KMP）、init 帧缺状态字段
   （vm 模块首帧崩溃"Cannot read properties of undefined (reading '0')"）——
   一律改为快照携带数据副本 + init 帧用 `...state()` 补全字段。
2. **TDZ 陷阱**：内层 `const isCur = isCur(i)` 与外层箭头函数同名 →
   "Cannot access before initialization"（折半查找踩过两次）。内层变量必须换名。
3. **全局污染**：所有经典 script 共享全局，模块顶层函数/常量**必须加前缀**
   （`_ks` `_sn` `_ca` `_vm` `_ad` `_hf` `_dj` `_hs` `_km` `_tp` `_sch` `_bk` `_sw` `_pl` `_ps` `_fa` `_ex` `_fb` `_bt` `_av` 等）。
4. **文件命名铁律**：模块文件统一 `ds-/coa-/os-/net-` 科目前缀（用户明确要求；**当前 38 个模块文件已统一**，
   原记 35 是窗1 时的数）。
5. **位移类动画（旋转 / 交换 / 重排）的架构：固定槽位 + 快照自带 `from` 坐标（窗2 新增，ds-bst-avl 实战）**：
   （这条讲"怎么让结点动起来"，与 §3.3「渲染/布局类」的版面经验互补；版面越界见 §3.3-12。）
   §1.3 的"每帧 `stage.innerHTML=''` 重建 DOM"意味着 **CSS `transition` 永远不会播放**——元素是新建的，
   一出生就在终值上，没有"属性变化"可过渡；**只有 `@keyframes` 会在新元素上重放**。
   所以要做"结点滑动"，必须凑齐三件事：
   - ① **让位移尽量简单**：把 x 固定成"该关键字在**最终**有序序列里的名次"（固定槽位），
     于是 BST 的插入与 AVL 的旋转（都**保持中序不变**）就**只改 y**，全树只有竖直位移。
     这一条是省掉后面所有麻烦的关键；
   - ② **快照自带上一帧坐标**：每帧存 `pos`（本帧坐标）与 `from`（**动作前**的坐标副本，用同一套纯布局
     函数算，零 DOM）。渲染端才不必回读 DOM 或猜起点（呼应 §3.1-1 自包含）；`from` 里缺的 id
     = 本帧新出现的结点 → 走"从父结点位置淡入"；
   - ③ **关键帧内联注入**：`<style>@keyframes _avN7{from{transform:translate(dx,dy)}to{transform:none}}</style>`
     拼进 `stage.innerHTML`（**必须放在 `<svg>` 之外**——HTML 解析器在 SVG 外来内容里对 `<style>` 的
     处理不稳妥），结点外侧 `<g transform="translate(x,y)">` 给**绝对值**、内层 `<g>` 只做**相对位移**动画。
     这样即使动画被禁用（`prefers-reduced-motion`）元素也停在正确位置。**全程零 style.css 改动**——
     §6.3-6 里窗0"AVL 旋转过渡大概率要动 CSS"的担心可以彻底放下。
   - **边怎么办**：边不能用纯平移跟随（两端位移向量不同）。因为①保证了所有位移都**纯竖直**，
     一条**相似变换**（translate ∘ rotate ∘ scale）就能把"终态线段"精确映回"初态线段"：
     `base = pNew − cNew`、`w = base + dP − dC`、`s = |w| / |base|`、`θ = atan2(w) − atan2(base)`、`t = dC`；
     关键帧 `from{transform:translate(t) rotate(θ) scale(s)} to{transform:none}`，线画在**孩子**的
     局部坐标系里（`x1=0,y1=0,x2=base`）。此式在 t=0 与 t=1 **精确**落位，中途也不脱节
     （推导与"用脚本反算验证"的断言写法见 §3.8-9）。
   - 顺带一条**语义**教训：双旋（LR/RL）要分两帧，**每一帧的高亮必须用"本步"的轴与上升结点**，
     不能沿用型判定时那一对——窗2 第一版就把第 2 步的 y 标错了人，而**断言全绿**，只有
     原分辨率截图看得出来（见 §3.6.1 与 §3.8-8）。
   - **补充（窗4 新增，ds-heap 实战）——"槽位天然固定"的模块不必走这条路**：§3.1-5 那套
     （固定槽位 + 相似变换跟随的边）是为了对付"结点位置随算法变化"的树。若模块的槽位**本身就是数据下标**
     （堆：完全二叉树的槽位 = 数组下标 1..n，形态只由容量 Nmax 决定），那么：① 槽位坐标是**纯函数**、
     与算法进度无关；② 父 ⌊i/2⌋ → 子 i 的**边完全静态**，不需要任何变换；③ 动的只是"槽位里装的元素"，
     渲染端仍用 §3.1-5② 的 `pos[id]`/`from[id]` 做平移。**代价是多一层"元素 ↔ 槽位"映射**
     （快照存 `arr[i] = {v,id}`，坐标按 id 记），好处是省掉最麻烦的边跟随推导。
     窗4 实测：ds-heap 零 style.css 改动、零相似变换。

6. **每个 `input` 都必须显式写 `default`（窗4 实测踩坑，ds-heap）**：`framework.js` 的 renderInputs 用的是
   `value="${inp.default}"`（textarea 同理），**缺 `default` 会渲染成字面量字符串 `undefined`**
   → 模块默认视图一打开就弹"输入有误"卡（本次是 `ins` 那个可选文本框）。
   ⚠ 更阴的是：**Node 冒烟会漏掉它**——冒烟的手写场景用 `base()` 覆盖了该字段、预设又都显式 `setInput`，
   只有"拿模块自带默认值 parse 一遍"才照得出来。**对策见 §3.8-11；§4.2 模板已同步标注。**

### 3.2 算法类死循环/逻辑 bug
5. **滑窗/可靠传输类模块的三个"永远跑不完"根因（窗3 就地改写，原条目只讲旧实现的序号环绕；三条都是窗3
   重写 net-window 时实测的，且全部被"每帧必然收敛 + guard 熔断"的冒烟抓住）**：
   ① **序号环绕**：不要用 `base % seqMax` 之类"取模后的序号"做已确认判据——全部序号确认后会沿环无限绕。
      用**真实帧号** Set（无环绕歧义）+ `base < total` 上界（窗0 旧实现踩过，窗3 沿用此口径）；
   ② **接收方在"一个按序帧都还没收到"时绝不能产生确认**：`k = max(0, rcvBase − 1)` 会吐出 `ACK 0`，
      发送方据此把 0 号帧标记为已确认、窗口却推不动，于是**超时→重传→被丢弃→再超时**无限循环
      （窗3 实测：GBN、丢 0 号帧、W=4 → 2400 次重传才被 guard 熔断）。正确口径：`rcvBase === 0` 时
      **没有确认可回**（`k = -1`），发送方只能等超时；
   ③ **"重复帧的再确认"不是冗余 ACK**：接收方对重复帧重发的 ACK 携带的是**真实信息**，发送方必须照常
      处理它；只有 `窗口没动 && 该帧本来就已确认` 才算真正的冗余确认。搞反了会死锁——窗3 实测：
      停等协议、ACK1 丢失（`A1:1`）时，接收方已交付 1 号帧、再收到重传的 1 号帧后回 ACK 1，
      若把它当"重复确认"忽略，就会无限重传。
   **教训**：这类模块的冒烟必须有"每帧只作为新帧发送一次""末帧必为 done（不是 guard）"两条硬断言，
   否则一个静默死循环会伪装成"跑得慢"。
6. **GBN 失序帧绝不能确认**（旧实现曾错推 `base`）：接收窗口 = 1，失序帧**丢弃**并重复 ACK 最后一个
   按序帧。**窗3 重写后**由 `receiverAct()` 里 `f === rcvBase` 这一个判据统一决定"收/丢"，
   结构上不可能再出现"既丢弃又确认"。
7. **GBN 批量重传时接收方期望必须逐帧推进**（旧实现用 `rcvrExpect` 漏推 → 后续新帧被误判失序 →
   多余超时，是用户报告"一直超时重传"的根因之二）。**窗3 重写后** `receiverAct()` 内联维护 `rcvBase`，
   每收一帧立刻推进，"忘了同步"这个失败模式已不存在。
8. **伪超时**（用户报告"一直超时重传"的根因之一）：主循环**不能无条件进入超时分支**——必须只在
   `base < next`（有在途未确认帧）时超时；`base === next`（窗口内全部确认）要**回到发新帧**。
   ⚠ **窗3 实测把这个判断写反过一次**：把"无事可做"分支写成 `break`，结果"只发了第一窗就结束"——
   冒烟一次抓到（§6.2 窗3 ⑤ 的第 1 个真 bug）。这条经验**不是历史**，重写模块时最容易再犯。
9. **DS-topo ve 清零**：`ve[u]=0` 无条件执行摧毁了前序松弛结果 → 工期恒 0、关键活动 0
   （用户红圈截图）。改为 `if (ve[u]===undefined) ve[u]=0`。
10. **挖坑法呈现**：快排划分中数组会出现"两个相同元素"的中间态（用户红圈困惑）。
    解法：快照加 `hole` 空位字段，渲染为虚线空框+"挖坑法进行中"提示条。
11. **批量改文本用"独立脚本 + 锚点校验"，不要用 shell 内联拼字符串（窗1 改写；原条目讲 Bash heredoc，
    在本机 Windows + pwsh 环境下已不适用）**：本机是 pwsh 且命令里禁管道（§3.5-9②），内嵌 `${}`、反引号、
    中文都容易被 shell 或编辑器吃掉。做法：用 Write 工具写一个临时 `tmp_*.js`（已被 .gitignore 覆盖），
    **把每处替换写成 `[旧串, 新串]` 列表，并断言"每个旧串恰好命中 1 处"，命中数不对就整体不写入**；
    大段改写用"起止锚点定位 + 切片替换"，别去精确复述几十行原文。窗1 用它一次改完 handover 71 处窗号
    （dry-run 先行）。用完删除（见 §3.5-18）。

    从发送方面板右侧飞到接收方面板左侧，而 **ACK 片比数据片宽**（文字 `ACK12✗` 更长）：
    沿用了数据片的行程 `tx = chR − chL − flyW` 后，ACK 片右端 = `chR − flyW + (flyW+10)`，
    **比数据片多出 10px，正好压住接收方面板 2px**（§3.8-3 的越界断言完全查不出来，只有原分辨率截图看得见）。

    并把这层检查写成**自动压盖断言**（见 §3.8-10），不要靠眼看。

    - ① **"交换前虚线幽灵"在两元素互换位置时会被对方结点整块盖住**——因为 A 的 `from` 恰好是 B 的
      `pos`、反之亦然。**这不是 bug**：动画播放**中途**两个元素都离开了原位，幽灵在那时才可见；
      而断言/截图前若注入了 `animation:none`（§3.5-10③），元素停在终值，幽灵必然被盖住。
      **别拿"停帧截图里看不见幽灵"当缺陷去查**（窗4 一度以为幽灵没渲染出来）。
    - ② **位移动画的中点侧向偏移能让两个对向移动的元素错开、不叠在一起**：关键帧写三档
      `from{…} 50%{translate(中点 + side×16×垂直单位向量)} to{transform:none}`，两侧 `side` 取相反数。
      **关键是 `to` 必须仍是 `transform:none`**——这样 t=1 精确落位、动画被禁用时也停在对的位置
      （断言写法见 §3.8-9）。

### 3.7 窗口粒度决策：一窗一模块 vs 一窗多模块（窗0 复盘，窗1 / 窗2 / 窗3 沿用）
> **结论：同类低风险模块「2 个/窗」最划算；跨书、跨范式、或要动 framework.js/style.css 的，仍是 1 个/窗。**
> **用户已拍板（2026-09-20）：粒度不再写死，改为"由当前窗口按本节规则给出【窗口建议】"**
> （输出模板与记录位置见本节第 6 条）；建议是推荐而非命令，**用户可否决**。

**成本结构（窗0 实测复盘；token 为粗估量级，非精确计数）**

| 成本项 | 性质 | 量级 | 说明 |
| --- | --- | --- | --- |
| 读 handover（560 行）+ 侦查定位 | 每窗固定 | ~10–15K | 省不掉，但要"grep 定位 + 只读相关行段" |
| 环境踩坑（沙箱 / 无外网 / Chrome 提权 / 服务器半路挂） | **一次性，已沉没** | 窗0 占大头 | 已沉淀为 §3.5-9~11、§3.5-16 与 §3.8-3，后续窗口照做≈0 |
| 真题逐题核对 | **一次性，已沉没** | 主线程不高（子代理承担） | 已由 `考情缓存/` 承接，后续 --ask 秒级 |
| 写模块（快照 + 渲染） | 每模块边际 | ~10K | 同类第 2 个更省：布局/动画/表格范式直接复用 |
| Node 冒烟（写脚本 + 跑 + 修） | 每模块边际 | ~5K | 同一套断言换场景即可复用，别每次重写 |
| 浏览器深测（harness + 逐帧 + 几何断言） | 以每窗固定为主 | ~8–12K | harness 生成与 CDP 驱动是固定的，多模块只多逐帧断言 |
| 全站 96 条遍历 | **每窗一次** | ~3–5K | 同窗 N 个模块只跑 1 次 → 多模块直接摊薄 |
| 五件套里的文档同步（README + handover） | **每窗一次** | ~8–15K | 同窗多模块合并成一次编辑，**省得最多** |
| 静态资源 `v+1` | **每窗一次** | ≈0 | 同窗多模块只递增一次 |

**为什么不是"越多越好"**：本模型（V4.1-Flash）在长上下文里的劣化是**可观测**的——窗0 后半段的失误
（并发跑了两次自检、把"本帧考察邻接点"芯片算进容器数、缩略图看错芯片数、Edit 报 file-changed）
**全部发生在多次工具调用之后**。上下文越长：① 重复读文件 / 重复验证变多（成本超线性）；
② "真 bug vs 测试脚本 bug"的判断力下降（§3.8-5）；③ 改一次共享文件（exam-history / index.html）
就让前面模块的验证证据过期，得重跑。

**建议的窗口粒度规则（可直接照做）**
1. **一批 ≤ 2 个模块**，且同时满足：同一本书 ／ 同一种图形或交互范式 ／ 不改 framework.js 与 style.css ／
   模式一致（都 stepper 或都 instant）。
2. **首选批量对象（范式可整体复用）**：
   - **instant 计算器家族**（进制转换、指令格式扩展操作码…）：范式几乎相同，**2~3 个/窗性价比最高**；
   - **"图 + SVG 节点/边"家族**（Prim 可直接复用 ds-kruskal / ds-dijkstra 的圆形布局与 `kedge-*` 动画）；
   - **"时序箭头"家族**（DNS / HTTP / 邮件：复用 net-tcp-conn 的报文箭头与两端状态机范式）；
   - **"树 + SVG"家族**（B 树复用 ds-bintree / ds-huffman 的树布局；**窗2 已完成 AVL 旋转，
     并把"结点位移动画"的通用做法沉淀成 §3.1-5（固定槽位 + 快照自带 `from` + 内联 `@keyframes`
     + 边用相似变换跟随）——后续任何"树/图里元素要动"的模块直接照抄这一节，不要再自己发明**）。
3. **必须 1 个/窗**：跨书；要改 framework.js / css（共享内核）；新图形范式（主存芯片连线、分层模型、波形图）；
   用户中途插需求；本窗已出现**未定位的真 bug**；某模块的 Node 冒烟修了 3 轮还没全绿。
4. **单窗熔断线**（触到任一条就收尾，不要再开新模块）：已产生 ≥2 个真 bug 且未复验；
   出现 ≥3 次"文件/文档状态失效"类返工；已完成 2 个模块而第 3 个刚开头。
5. **每窗只做一次 vs 每模块立刻做**：
   - 每窗一次：全站 96 条遍历、README/handover 同步、`v+1`、`tools/doc_check.py`；
   - 每模块立刻做：属于它的五件套（模块文件 / app.js 转 ready / exam-history 条目 / index.html 脚本标签）
     + 自己的 Node 冒烟 + 浏览器深测（**先做完再开下一个模块，不要攒**）。
6. **【窗口建议】机制（用户明确要求，2026-09-20 起必做）**：窗口粒度不再写死，改由**当前窗口**负责推荐。
   - **何时给**：每个模块做完时给一次简短版（是否继续做下一个），**窗口收尾时给最终版**。
   - **写在哪**：① 回复用户时明确写出；② 覆盖更新到 **§6.5「本窗窗口建议」**（一节只留最新一条，顶部写 `【窗N】`），
     这样下一个窗口开场就能看到上个窗口的推荐；同时到 **§6.6 窗号台账**追加一行（最新在上，见 §1.7-4）。
   - **怎么给**（照这个模板，量化、可核对，不要只写"感觉可以继续"）：
     ```
     【窗口建议】建议：继续（下一个做 X）/ 换窗
     - 本窗已完成：<模块 n 个> + <基础设施/文档改动>
     ```

14. **沙箱里"把输出落盘再读"的正确姿势（窗1 实测）**：不要用 shell 的 `>` 接 python：
   `& 'D:\anaconda\python.exe' tools/exam_index.py --ask "B树" > tmp_q.txt` 得到的是 **0 字节空文件**
   （命令本身 exit 0，看不出失败）。原因族系是 PowerShell 重定向流与脚本内部
   `sys.stdout.reconfigure(encoding='utf-8')` 相互干扰。两条可用做法：
   ① **不加 `>`**，直接让输出打到控制台看（`--ask` 命中一般 ≤60 行，够读）；
   ② 要落盘就**在 python 里自己写文件**（`io.open('x.txt','w',encoding='utf-8')`）。
   另：临时 python 脚本若 print 中文/生僻字（缓存里 OCR 出了 `ę` 这类字符），在 **gbk 控制台**下会
   `UnicodeEncodeError` 直接崩——脚本开头一律加
   `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`（窗1 的 `tmp_btree_scan.py` 就崩过一次）。
15. **新模块的"预设按钮"必须机器验证，别只靠眼看（窗1 踩坑）**：窗1 写了一个删除演示预设，
   标签写"借位 → 合并 → 根降高"，实际快照里**根本没有 shrink 帧**——纯属文案想当然。
   做法：冒烟脚本里用**假 `rt`**（`{setInput(k,v), load(){}}`）把 `def.quickActions` 逐个跑一遍
   收集输入值，既验证"每个预设都能跑通"，又能断言"标签承诺的动作真的出现了"。
   同一招还能免费覆盖所有预设的逐帧渲染（窗1 的 6 个预设全部纳入冒烟，改预设后自动回归）。
16. **开工先跑三条环境探针（窗0 教训，窗1 整理上移；不跑就可能连撞好几轮）**：

21. **harness 与 CDP 的四个"版本漂移"坑（窗3 新增，全部实测；上一版做法已就地改写）**：
   ① **`/json/new` 现在只收 PUT**：Chrome 153 上 `fetch('http://127.0.0.1:9222/json/new?<url>')`（GET）
      返回纯文本 `Using unsafe HTTP verb GET to invoke /json/new...`，`JSON.parse` 直接崩
      `SyntaxError: Unexpected token 'U'`。**必须 `fetch(url, { method: 'PUT' })`**；
   ② **别指望 `Runtime.evaluate` 拿到 Runner**：`app.js` 把 Runner 关在 IIFE 里、**没有挂到 `RC408`**
      （`RC408.runner` 不存在）。可用入口只有 **`RC408.openTopicFromUI(id)`** 与
      `ctl-load / ctl-reset / ctl-step / ctl-play / ctl-seek` 这几个 DOM
      （`ctl-seek` 要用 `new Event('input',{bubbles:true})` 触发）。逐帧渲染则**不要走 Runner**：
      直接 `def.parse(vals)` + `def.buildSnapshots(model)` + `def.render({model,snap,idx,total,stage})`，
      与冒烟脚本完全同一套，省掉一半适配；
   ③ **`Page.captureScreenshot` 的 `clip` 不可靠**：带 `captureBeyondViewport:true` 时按页坐标解释、
      不带时又像按视口解释；窗3 两种都试过，两次都截到了目录树而不是 stage。
      **改用最稳的一招**：给 harness 加 `body.harness-zoom` 类，`display:none` 掉目录/理论卡/日志卡/
      输入区/控制面板/步骤条，并把 `#stage svg{width:1560px}` 撑满视口，然后**整屏截**（不带 clip）——一次就成；
   ④ **别用"滚动 + 裁切"定位 stage**：harness 里 `#main-section` 的 `scrollHeight === clientHeight`
      （它没成为滚动容器），真正滚动的是**文档**；且内容总高 > 视口时 `scrollIntoView` 会被 clamp，
      stage 只能停在视口中部（窗3 实测 y=506）。按 ③ 隐藏无关面板即可，不要折腾滚动。
   另：`--window-size=1600,1700` 足够同时放下"完整 stage 截图"与"放大 SVG 截图"两种需求。
   ⑤ **"放大只看 SVG"那张图要按整页高度截（窗4 新增）**：`harness-zoom` 把 SVG 撑宽后，
   `H/W` 比例大的模块（ds-heap 的完全二叉树 W=560/H=413）总高会超过视口，
   **不带 `captureBeyondViewport` 的整屏截会把数组行直接切掉**——窗4 第一版截图就是这样，
   差点漏掉"数组行 / 交换弧线 / 已取出序列"整块版面没验。做法：`Page.captureScreenshot({format:'png',
   captureBeyondViewport:true})`，缩放到 `#stage svg{width:1240px}` 即可一屏装下。

### 3.8 验证与自检方法论（**与模型无关，通用**，窗1 从 §3.6 上移并整理；窗2 新增第 9 条；窗3 新增第 10 条；窗4 新增第 11 条与 §3.8-3④）
> 本节回答"凭什么证明这个模块是对的"。**任何模型、任何窗口都照此执行**；
> 模型特有的失误倾向见 §3.6（按模型分小节）。窗1 上移时把"某模型的倾向"剥掉了，只留下可照做的做法。

1. **断言只写不变量，绝不写"我算出来的常量"**：可用不变量举例——B 树：每帧关键字集合 = 前 n 个插入 −
   前 m 个删除、所有叶结点同层、稳定帧必为合法 m 阶树；图：生成树边数 = n − 分量数、访问序列无重复顶点。
   **必须写常量时，用第二条独立路径复核**（窗1：高度公式用 2013-10 / 2014-9 / 2025-8 三道真题反证；
   这三题同时把"m 阶 = 最多 m−1 个关键字"的口径钉死）。
2. **先分清"稳定帧"与"过渡帧"，再套结构公式**：算法中间帧本来就不是合法状态（溢出帧有 m 个关键字、
   下溢帧低于下限、分裂/合并中途孩子数在变），把公式套上去只会得到一片假红。
   写法：先算 `structValid`（每个结点关键字数在限内、根非空），为真才套公式；**同时额外断言
   "稳定帧（init / settled / done）必须 structValid"**——既不误报，又真正盯住收尾状态。
   （窗1 第一版冒烟 208 条红，全部是这一步没做对；改完后 44 场景 / 89372 项断言全过。）
3. **版面问题分三档验，别只会截图**：
   ① **越界 / 裁剪**（文字跑出 viewBox）→ `getBBox()` 断言，最可靠（窗1 靠它精确点名
      `<text> text="根" bbox=(121.5,-4.7,11.3,16.0)`，肉眼看只会觉得"顶部有点挤"）；
   ② **压盖 / 重叠**（箭头压在框上、标签压住结点）→ **几何断言查不出来**，必须看**原始分辨率**截图
      （`Page.captureScreenshot({clip})` 裁到元素，或隐藏理论卡/日志卡后 `scrollIntoView(stage)` 整屏截）；
   ③ **缩略图只用来找可疑处**，不用来下结论（百分比缩放下最容易看错）。
    ④ **`getBBox()` 给的是"元素自身局部坐标"，带 `transform` 的图元会误报越界（窗4 实测，8819 条假红）**：
     结点画在 `<g transform="translate(x,y)">` 里时，`getBBox()` 返回的是 `(-r,-r,2r,2r)`，
     既会一片"越界"、也会让"结点两两相碰"断言全红。**越界/压盖断言一律用
     `getBoundingClientRect()` 与 svg 自己的 `getBoundingClientRect()` 比**（屏幕坐标，viewBox 缩放与
     祖先 transform 都已算进去）；`getBBox()` 只适合"整张 svg 里没有任何 transform 图元"的模块。
     窗4 改用屏幕框后：483 帧 0 越界、0 压盖、0 结点相碰。
4. **同一个自检只能跑一次**：页面加载自动跑一次 + 手动再跑一次，两次遍历会互踩状态、误报一片。
   要重复验证，先确认前一次的产物已落盘、相关进程已结束。
5. **红一片时先归三栏**：`真 bug / 测试脚本 bug / 环境噪声`，归类后再定性（两窗实测见 §3.6.1）。
6. **"自己写的文案/标签"也是断言**：预设按钮标称的动作、theory 里的年份、"树高 +1"这类 desc 文案，
   都要用脚本与快照事实对起来（手法见 §3.5-15）。**判据：凡我写死的常量或文案，要么机器复核过，要么不写。**
7. **冒烟场景要"自驱动"，别手写清单**（手法见 §3.5-15，此处只留原则）：**场景清单必须从模块自身导出**
   ——从 `def.quickActions` 反推，改预设后自动回归，顺带验证"每个预设都能跑通"。
   窗1 实测：44 场景 = 8 条手写 + 6 个预设 + 30 组随机，改一次预设无需改冒烟脚本。
8. **几何断言 + 肉眼截图，两样都要**：一档越界靠断言、二档压盖靠截图（窗1 两个版面 bug 一边一个）。
   **只靠其一都会漏。**
9. **动画类模块要断言"关键帧的起止落在数据算出的坐标上"，不能只断言"生成了 animation"（窗2 新增）**：
   做法——冒烟脚本用正则把渲染出来的 `@keyframes` 抓出来，按模块自己的变换公式**反算**端点坐标，
   与快照里的 `from` / `pos` 对齐。窗2 对 ds-bst-avl 的**每条边**都断言了
   "t=0 时线段两端的绝对位置 == 两端结点各自的上一帧坐标"，共 **13 万余项**断言（构造见 §3.1-5）。
   **这条专门抓"动画看着对、其实已经脱节"的 bug**——越界断言与结构断言都查不出它。
   配套的**二档**手段：把动画**停在中途**截图——先 `document.querySelector('style').disabled = true`
   恢复动画，seek 到目标帧后等 ~300ms 再 `Page.captureScreenshot`，肉眼确认边是否还贴在结点上。
   窗2 用它确认了相似变换方案（截图见 §6.2 记录）。
   **反面教材（窗2 实测）**：13 万项断言 + 几何断言**全绿**，却漏掉了"双旋第 2 步高亮标错人"这个
   真 bug——**是原分辨率截图抓到的**。所以"断言全绿"绝不能代替二档截图。
10. **"压盖"也能自动断言——把二档的一部分从"靠眼看"变成"靠脚本"（窗3 新增，net-window 实证）**：
    §3.8-3② 说"重叠查不出来、只能看截图"，那是针对**任意图元两两相交**（那样误报太多）。
    但**关键的几对**是可以精确断言的，命中率极高、误报极低：
    - 做法：给"会动的图元"和"不能压的地标"各加一个可查询的标识（窗3 用
      `g.sw-frame-g rect` 对 `rect[fill="#eef2ff"] / rect[fill="#f0fdfa"]`，即信道上的飞行片 vs 两侧面板），
      遍历**每一帧**取 `getBBox()` 判相交，相交即失败并打印**两边的坐标区间**。
    - 窗3 用它自动确认了 §3.3-20 那个 bug（ACK 片比数据片宽 10px → 右端压住接收方面板 2px）；
      这条断言写进 harness 后，以后改面板宽度/改片宽都会立刻报红。
    - **前提**：断言要跑在"动画已停"的状态（§3.5-10③ 的 `harness-noanim`），否则 `getBBox()` 取的是
      起点位置、看不出终点是否越界。
    - **分工不变**：自动断言负责"这几对明确的图元"；② 那条"任意图元互相压盖"仍然要看原分辨率截图。
      窗3 依然是**先看截图发现、再补断言**——顺序别反：断言只能防回归，发现新问题还是得靠眼睛。

11. **"模块自带的默认输入必须能跑通"要写成断言（窗4 新增，ds-heap 实测）**：`framework.js` 渲染输入框用
    `value="${inp.default}"`，**input 缺 `default` 会渲染成字符串 `undefined`**，默认视图一打开就是
    "输入有误"卡（详见 §3.1-6）。这条**冒烟极容易漏**：手写场景用 `base()` 覆盖了字段、预设又都显式
    `setInput`，全都会绕过默认值。**冒烟必须补两条**：
    ① `def.inputs.forEach(i => 断言 i.default !== undefined/null)`，select 还要断言 default 出现在 options 里；
    ② **把 `def.inputs` 的默认值直接喂给 `def.parse()` 并跑完整 buildSnapshots**（断言不抛错、末帧是 done）。
    窗4 的 87 场景 / 77 万断言**全部漏掉了这个真 bug**，是浏览器**全站 96 条遍历**那一栏报
    `stage err ds-heap` 才暴露的——**"默认视图"是浏览器的视野，不是冒烟的视野，两边都要有。**
