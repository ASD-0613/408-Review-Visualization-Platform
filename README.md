# 考研 408 复习可视化平台

将 408（数据结构、计算机组成原理、操作系统、计算机网络）的抽象知识点转化为**可操作的交互式可视化**：
用户单步执行 / 拖动滑块 / 修改输入，界面即时给出节点变色、连线高亮、数据流动、状态切换等反馈。
不是播放视频，而是"每一步都亲手推"。

**模块选题依据真题数据驱动**：平台内置知识点全部对照 `408真题及解析/`（2009–2025 共 17 年统考真题）
的考点统计与 `考纲/25考研408大纲.pdf` 选取与排序，各模块理论区顶部附有「📊 真题考情」标注，
完整统计见本文末尾 [真题考情分析](#-真题考情分析20092025)。

## 三、核心架构：快照（Snapshot）模式

**算法与 UI 严格分离。** 每个可视化模块把一次完整演示"一次性"算完，输出**状态快照数组**；
界面只维护一个下标 `idx`：

```
parse(表单值)  ──▶  buildSnapshots(model)  ──▶  Snapshot[]          ← 纯算法，零 DOM、可测试
                                                     │
Runner（idx++ / 重置 / 拖动进度条 / 自动播放）          ▼
                                     render({ model, snap, idx, total, stage })   ← 纯渲染，读快照画界面
```

由此带来三个结果：

1. **标准控制面板零成本复用**——"生成数据 / 重置 / 单步 / 自动播放 / 速度 / 进度拖动"全部退化为
   移动 `idx` 后重绘，由 `framework.js` 的 Runner 统一提供；
2. **日志与画面永远一致**——日志直接由 `[0..idx]` 区间快照重建，回退、拖动时自动同步；
3. **动画即状态**——"红闪 2 次 / 上飘消失 / 滑入"都是渲染器给**当前帧变化的元素**附加 CSS 动画类，
   下一帧重建 DOM 后自然回到稳态，无需手动管理动画生命周期。

### Runner 生命周期

```
open(topicId)                    ← 点击目录树条目
  ├─ 未注册 → 渲染"敬请期待"占位页（显示 plan 字段）
  └─ 已注册 → 渲染理论区(Markdown) → 渲染输入表单(inputs 配置) → 渲染控制面板
              └─ load()：parse(表单) → buildSnapshots(model) → idx=0 → paint()
paint()
  ├─ def.render({ model, snap, idx, total, stage })   ← 模块自渲染当前快照
  ├─ 更新步骤说明条（snap.desc）与进度
  └─ syncLog()：由 snaps[0..idx] 重建日志
```

### 两类模块模式

| 模式 | 适用 | 控制面板 |
| --- | --- | --- |
| `mode:'stepper'` | 有过程演进的演示（绝大多数） | 完整：生成数据/重置/单步/自动播放/速度/进度 |
| `mode:'instant'` | 无过程、参数即结果（如子网划分） | 精简：提示"修改参数即时生效" |

输入联动约定：**下拉框（select）变更 → 立即 load() 重新生成**；文本/文本域变更 → 显示
"参数已修改"提示，由用户手动点「生成数据」（避免输入中途被打断）。

## 四、新增模块开发指南

### 第 1 步：创建 `js/modules/你的模块.js`

按以下契约实现并注册（以"最短可用骨架"为例，实际每个模块还可加 quickActions / bindInputs）：

```js
'use strict';
RC408.registerModule({
  id: 'ds-xxx',                    // 全局唯一，与 app.js 目录条目一致
  mode: 'stepper',                 // 'stepper' 单步型 | 'instant' 即时型
  title: '模块标题',
  theory: `
    > 📊 **真题考情**：…（哪几年考、什么题型、分值）
    ## 概念 …  ## 伪代码 …  ## 考点提示 …          // Markdown，支持表格/代码块/引用
  `,
  inputs: [                        // 数据驱动生成表单
    { key: 'seq', label: '…', type: 'textarea', rows: 2, wide: true, default: '…', help: '…' },
    { key: 'mode', label: '…', type: 'select', default: 'a', options: [{ v: 'a', t: '方式A' }] },
    // type 还支持 text / range（配 min/max/step，显示 /N 徽标）
  ],
  quickActions: [                  // 表单区快捷按钮（随机生成 / 真题预设）
    { label: '🎲 随机', run(rt) { rt.setInput('seq', '1,2,3'); rt.load(); } },
  ],
  parse(vals) {                    // ① 校验并解析表单，失败 throw {message} → 界面显示错误卡
    return model;
  },
  buildSnapshots(model) {          // ② ★ 纯算法：一次性产出全部快照
    return [ { log: '…', logType: 'info', desc: '…' /* + 各帧视觉状态字段 */ } ];
  },
  render(ctx) {                    // ③ ★ 纯渲染：按 ctx.snap 绘制到 ctx.stage
    ctx.stage.innerHTML = `…`;
  },
});
```

### 第 2 步：注册到平台（两处）

```html
<!-- index.html 末尾，按书籍分组插入一行 -->
<script src="js/modules/你的模块.js"></script>
```

```js
// js/app.js 对应书籍章节里加条目

// 或建设中占位：{ id: 'ds-xxx', label: '…', status: 'wip', hot: true, plan: '规划中的交互描述' }
```

### 第 3 步：自检清单

- [ ] 快照携带**全部**视觉状态（渲染函数除 `ctx.snap` 外不得读取任何可变外部状态）；
      需要全局时序的（如 Runner.snaps、RC408.Runner.idx）只作只读使用
- [ ] `parse` 对一切非法输入 `throw {message}`，错误卡能正确显示中文提示
- [ ] 快照数量有上限（单步演示 ≤ ~60 帧，输入长度/数量在 parse 中拦截）
- [ ] 文件内所有顶层标识符带模块前缀，`node --check js/modules/你的模块.js` 通过
- [ ] 浏览器实测：单步到最后一帧、拖动进度条来回、自动播完自动停、日志随回退一致
- [ ] theory 顶部有「📊 真题考情」块（数据见下文统计，注明年份）
- [ ] **选题已对照考纲**：确认该考点在《25 考研 408 大纲》内，且不在第五节
      "已删考点对照表"中；若用户日后反馈大纲调整，用 `legacy` 字段把条目转为考纲外标注

### 常见坑

1. **动画不重放**：动画类挂在"当前帧变化的元素"上，每帧 `stage.innerHTML = ''` 重建 DOM
   才会重新触发；不要试图常驻 DOM 做补间。
2. **快照丢失状态**：只存"增量"会导致回退/跳帧渲染错误；每帧必须存全量副本
   （`JSON.stringify` 或手工展开拷贝，注意引用数组要 `[...arr]`）。
3. **`this` 指向**：`parse/buildSnapshots/render` 以 `def.parse(vals)` 方式调用，`this` = 模块
   定义对象，可安全读取模块级常量；但不要把**可变状态**放模块对象上（会跨演示残留）。
4. **全局污染**：见第二节命名铁律。
5. **instant 模式没有快照**：`render(ctx)` 只收到 `{model, inputs, stage}`，日志用可选的
   `logs(model)` 方法返回 `[{text, type}]`。

### 结论（对建设的指导）

1. **OS 的 PV 大题**与**计组的 Cache/补码**是性价比最高的三件事，已全部落地；
2. 计网大题几乎固定为"网络综合分析"（子网划分 + 设备选型 + 协议交互），`net-subnet` 已覆盖核心计算，
   剩余部分适合做成"真题情境复演"类模块；
3. 数据结构大题是**算法设计题**（链表/数组/图），不适合逐帧动画，建议未来的形式是
   "代码执行单步器"（C 伪代码逐行高亮 + 变量/结构体状态面板）而非图形动画；
4. 每年稳定出现的**送分题型**（复杂度分析、栈输出序列、编码波形）适合做成"计算器型"即时模块。

## 七、约束与已知问题

- Tailwind 由 Play CDN 提供：**离线打开样式会缺失**（有检测提示条）；如需完全离线，
  可引入 Tailwind CLI 生成的静态 CSS 替换 CDN 行。
- 展示区缩放使用 CSS `zoom` 属性（Chromium/Edge/Firefox 126+/Safari 支持；老浏览器自动忽略）。
- **本地服务器预览时的浏览器缓存**：用 `python -m http.server` 预览时，修改 js/css 后刷新
  可能仍是旧文件（子资源被缓存）。仓库提供了 `serve.py`（响应带 no-store 头）解决：
  `python serve.py [端口]`。双击 `index.html`（file:// 协议）不受此影响；
  `index.html` 中静态资源带 `?v=N` 版本参数，**每次修改 js/css 后请把 N 加一**。
- 模块间通过全局命名空间 `RC408` 通信；删除/改名模块文件后务必同步 `index.html` 与 `app.js`。
- `408真题及解析/` 与 `考纲/` 目录是资料，平台运行**不依赖**它们，可随意移动仓库位置；
  这两个目录（真题/解析 PDF 与考纲 PDF）**不纳入 Git 仓库**（.gitignore 已排除），
  克隆仓库后自行放入同名目录即可恢复完整的考情分析数据来源。
- 理论区顶部的「📊 真题考情」块是每个模块的固定栏目：新增模块时必须按 README 第五节的
  统计数据填写（格式：考频 ×/17 + 考过年份 + 常见题型），保持全站一致。
